# 运维操作

> [!info] 上下文 [[00-总览]] · 部署 [[20-部署流程]] · 故障 [[50-故障排查]]

最常用的服务器端操作。大部分能通过主菜单 `./manage.sh` 完成。

## 重置用户密码

> [!tip] 场景
> 忘记了首次自动生成的密码 / bcrypt 哈希因 shell quoting 损坏导致登录失败 / 想换个密码

### 方法 1：主菜单（推荐）

```bash
./manage.sh
# 选 [2]
# 提示：用户名（默认 admin）→ 直接回车
# 输入新密码（隐藏） → 再次确认
# ✓ 已重置 admin 密码
# hash 前缀: $2b$12$xxxxxxxxxxx...
```

立即用新密码登录。**不需要重启容器**，**不需要 pull 新镜像**。

### 方法 2：用 cli

```bash
docker compose exec app python -m app.cli reset-password --username admin --password 你的密码

# 或交互式（密码不进 history）
docker compose exec app python -m app.cli reset-password --username admin
```

> [!warning] `reset-password` 不会顺手提权
> 对已存在的用户，只改密码、不动 `is_admin`。要提权必须显式加 `--make-admin`。
> 早期版本会静默把任意用户改成管理员 —— 那意味着谁都能看到全部租户的数据，
> 而且没有任何痕迹。相关命令：
>
> ```bash
> docker compose exec app python -m app.cli list-users              # 谁是管理员
> docker compose exec app python -m app.cli set-admin --username X        # 提权
> docker compose exec app python -m app.cli set-admin --username X --off  # 撤销
> ```

### 方法 3：紧急 inline（最底层兼容）

```bash
docker exec -e NEW='你的密码' douyin-spark python -c "
import os, bcrypt
from app.db import SessionLocal, init_db
from app.models import User
init_db()
h = bcrypt.hashpw(os.environ['NEW'].encode()[:72], bcrypt.gensalt(12)).decode()
with SessionLocal() as db:
    u = db.query(User).filter(User.username == 'admin').first()
    if not u:
        u = User(username='admin', password_hash=h, is_admin=True, is_active=True,
                 max_accounts=100)
        db.add(u)
    else:
        u.password_hash = h; u.is_active = True; u.is_admin = True
    db.commit()
    print('done')
"
```

## 查看日志

### 主菜单 [3]
```bash
./manage.sh
# 选 [3]
# 显示 docker compose ps + 最近 30 行 logs
```

### 实时跟踪
```bash
cd /opt/douyin-spark
docker compose logs -f
```

### 按关键词
```bash
# 看 admin 密码（首次启动）
docker compose logs | grep -A 8 "管理员账户"

# 看启动时的 DB 迁移
docker compose logs | grep "init_db"

# 看错误
docker compose logs | grep -iE "(error|warning|❌|⚠)"

# 看自动续火花的执行结果
docker compose logs | grep -E "\[auto\]"
```

## 数据备份

数据是 **bind mount**，不是 docker volume —— 直接就是宿主机上的一个目录，
`tar` 一下就完事，不用起一次性容器去掏 volume。

### 备份

```bash
cd /opt/douyin-spark
docker compose stop                                   # 停机备份最干净
tar czf ~/spark-backup-$(date +%F).tar.gz data/ .env
docker compose start
```

SQLite 开了 WAL，热备（不停机）基本也安全，但升级前建议还是停一下。

### 恢复

```bash
cd /opt/douyin-spark
docker compose down
rm -rf data/
tar xzf ~/spark-backup-2026-09-04.tar.gz
docker compose up -d
```

> [!danger] 备份文件 = 一堆凭证
> `data/` 里有所有抖音号的 cookies 和私钥，`.secret_key` 是解开它们的钥匙。
> 当成密钥文件保管，别丢进公开的对象存储或网盘。

## 停止 / 启动

```bash
docker compose stop      # 停（保留数据）
docker compose start     # 启
docker compose restart   # 重启
docker compose down      # 停 + 删容器（data/ 目录不动）
```

## 升级到新版本

```bash
docker compose pull       # 拉新镜像
docker compose up -d      # 重建容器（自动用新镜像，data/ 不变）
```

或主菜单 [1] 选 N（不重新配置） → 自动 pull + up -d。

DB 迁移在启动时自动跑，不需要手动执行任何迁移命令。
