# 授权码签发与客户交付

## 先区分两种码

| 名称 | 用途 | 生成位置 | 是否需要客户机器码 |
|---|---|---|---|
| 用户授权码 | 用户注册后兑换使用时长和账号数 | Web 管理后台 `/admin/codes` | 否 |
| License Key | Docker 应用启动许可 | 本地 `tools/issue_license.py` | 仅严格绑定时需要 |

> [!warning] 不要混用
> 用户授权码通常是 16 位大写字母/数字；License Key 是带 `.` 分隔的很长字符串。`tools/issue_license.py` 生成的是 License Key，不是用户兑换码。

## 一、生成用户授权码

> [!danger] 必须在**客户实际访问的那个实例**上生成
> 用户授权码存在该实例自己的 SQLite（`data/app.db` 的 `license_codes` 表）里，
> 不是签名生成的、也不能跨实例通用。
> 在本地 `127.0.0.1:8765` 生成的码，客户在 `https://dy.mrsong.top/activate`
> 兑换只会得到「授权码不存在」—— 两个库根本不是同一个。
> 线上客户用的码，就去线上后台生成。

### 前提：线上得有管理员账号

`ensure_admin()` 只在 `.env` 同时配了 `ADMIN_USERNAME` 和 `ADMIN_PASSWORD_HASH`
时才会 upsert 管理员。没配的话启动日志会打印：

```
[bootstrap] 警告：.env 未配置 ADMIN_USERNAME / ADMIN_PASSWORD_HASH
```

此时没有任何自动保障机制，先确认现状：

```bash
docker exec douyin-spark python -m app.cli list-users
```

没有管理员、或密码忘了，就直接改库（不用重启容器）：

```bash
# 已存在的用户：只改密码，权限保持不变
docker exec -it douyin-spark python -m app.cli reset-password --username admin

# 需要新建一个管理员
docker exec -it douyin-spark python -m app.cli reset-password \
  --username owner --make-admin
```

> [!warning] 改密码默认**不会**提权
> 旧版本的 `reset-admin`（以及 `manage.sh`/`manage.ps1` 的 [2]）无条件把目标用户
> 设成管理员，给普通用户重置一次密码就让他能看到全部租户的数据，提示语还只说
> 「已重置密码」。现在必须显式加 `--make-admin`。
> 误提权了用 `python -m app.cli set-admin --username X --off` 撤销。

### 生成

1. 用管理员账号登录线上站点，打开 `/admin/codes`。
2. 填四个字段后提交：

| 字段 | 含义 | 默认 | 上限 |
|---|---|---|---|
| `duration_days` | 兑换后增加的天数 | 30 | — |
| `count` | 本次生成几个码 | 1 | 200 |
| `max_accounts` | 该用户可绑几个抖音号 | 1 | 100 |
| `note` | 备注，只给你自己看 | 空 | 200 字 |

3. 列表页复制短码发给客户；批量发货用 `/admin/codes.csv?filter=unused` 导出未使用的。

码是 16 位，字母表 `ABCDEFGHJKLMNPQRSTUVWXYZ23456789` —— **去掉了 I/O/0/1**，
避免客户手抄时把 O 认成 0。校验时会自动 `strip()` + 转大写，客户小写粘贴也能过。

### 客户怎么用

注册账号 → `/activate` 输入短码 → 立即生效。兑换语义有两条容易踩：

- **时长叠加**：当前未过期就从原到期日往后加，不是从今天重算 —— 提前续期不会吞掉剩余天数。
- **配额只升不降**：`max_accounts` 取 `max(现有, 码里的值)`。给已有 5 个配额的客户发一张
  `max_accounts=1` 的月卡，不会把他砍到 1。

兑换是**原子**的：用条件 UPDATE + rowcount 判定，并发下只有一个事务能把 `used_by`
从 NULL 改掉，其余的 WHERE 匹配不到行。一码多用 = 直接收入漏损，所以这里没有
「先查后写」（SQLite 不支持 `SELECT ... FOR UPDATE`，SQLAlchemy 会静默忽略）。

### 撤销与排错

未使用的码可以在 `/admin/codes` 点「撤销」（写 `revoked_at`）。**已兑换的撤销不了** ——
权益已经落到用户身上了，要收回得去 `/admin/users/{id}` 调到期时间。

客户兑换失败时，`/activate?error=` 里的值对应：

| error | 含义 |
|---|---|
| `code_format` | 不是 8~24 位大写字母数字，多半是粘贴带了空格或漏字符 |
| `code_not_found` | 这个库里没有这个码 —— **最常见的是码生成在了另一个实例** |
| `code_used` | 已被兑换过 |
| `code_revoked` | 你撤销过 |

每次兑换都会写 `AuditLog`（`action=activate_code`），在 `/admin/audit` 可查。

## 二、生成部署 License Key

### 宽松模式：不绑定机器

适合自用部署，或你信得过、不担心复制部署的客户：

```bash
cd /Users/apple/code/python/抖音续火花
python3 tools/issue_license.py \
  --days 365 \
  --tier pro \
  --note "客户A"
```

> [!warning] 想清楚再发
> 不绑定的 License 在**任何机器**上都能用，而且校验是离线的、**无法吊销**。
> 一旦发出去，客户想部署几份就几份，你也收不回来。
> 需要限制复制部署就直接走下面的严格模式 —— 取机器码并不需要先发一张能用的 License。

把命令输出的完整长字符串交给客户，写入客户服务器的 `.env`：

```ini
LICENSE_KEY=这里粘贴完整长字符串
```

### 严格模式：绑定客户机器

适合大客户或需要限制复制部署的场景。

> [!danger] 千万别为了取机器码先发一张不绑定的 License
> 不绑定的 License 是**任何机器都能用、离线无法吊销**的永久通行证。
> 发出去就收不回来：客户没有任何理由再换成绑定版，还能拿它部署十份。
> 下面的流程全程不需要一张可用的 License 离开你手里。

机器码取自数据卷里的 `.install_id`（首次启动自动生成，跨容器重建/镜像升级都不变）。
关键点：**校验失败的横幅本身就会打印机器码**，所以客户用一个无效 key 启动一次就够了。

客户端操作：

```bash
# .env 里随便填一个无效值，容器会起不来，但机器码已经生成并打印
echo 'LICENSE_KEY=x' >> .env
docker compose up -d
docker compose logs | grep 当前机器码
```

输出形如：

```
────────────────────────────────────────
  ❌ 许可验证失败
────────────────────────────────────────
  License 格式错误（应形如 <payload>.<signature>）
────────────────────────────────────────
  当前机器码：b50508c79b2cf9a4
────────────────────────────────────────
```

`.install_id` 此时已经落进挂载的 `/data`（权限 600），之后每次启动读到的都是同一个码。

若容器已经在正常运行，也可以直接取：

```bash
docker exec douyin-spark \
  python -c "from app.license import _machine_id; print(_machine_id())"
```

> [!danger] 不要用 `docker run --rm` 取机器码
> 临时容器没有挂载客户的数据卷，会现场生成一个随即被丢弃的 `.install_id`，
> 拿到的码是错的，签发后客户依然启动不了。

客户把输出的 16 位机器码发给卖家。卖家签发：

```bash
cd /Users/apple/code/python/抖音续火花
python3 tools/issue_license.py \
  --days 365 \
  --tier pro \
  --machine 客户机器码 \
  --note "客户A-严格绑定"
```

客户服务器的 `.env` 只需要配置：

```ini
LICENSE_KEY=这里粘贴完整长字符串
```

### 要给试用怎么办

签一张**短效**的不绑定 License，让它自己过期，而不是发长期的：

```bash
python3 tools/issue_license.py --days 3 --tier basic --note "客户A-试用"
```

> [!important] 绑定不需要、也不接受开关
> 签发时绑了机器码，校验就无条件生效。`LICENSE_STRICT` 已废弃：
> 它曾经由客户端环境变量控制，客户删掉就能解绑，等于没绑。

然后重启并检查：

```bash
docker compose restart
docker compose logs --tail 30 | grep -A 5 "License 已验证"
```

看到 `机器绑定: 严格 · <机器码>` 才表示绑定已生效；未绑定的会显示 `机器绑定: 未绑定`。

> [!important] Docker 注意事项
> 机器码来自数据卷里的 `.install_id`，所以取码命令必须跑在挂载了 `/data` 的正式容器里（`docker exec`）。
> 直接在宿主机跑 Python、或用 `docker run --rm` 起临时容器，拿到的都不是客户真正的机器码。

## 换机器或机器码不匹配

报错 `License 绑定的机器码与当前不匹配` 时：

1. 客户在正式容器里重新取机器码（见「严格模式」一节的 `docker exec` 命令）。
2. 卖家使用新机器码重新签发 License Key。
3. 客户替换 `.env` 中的 `LICENSE_KEY` 后执行 `docker compose restart`。

> [!note] 备份恢复
> `.install_id` 在数据卷里，备份 `data/` 目录即可保留机器码；
> 客户按 [[30-运维操作]] 的方式整目录恢复后，绑定的 License 仍然可用。

如果需要临时解绑，只能由卖家重新签发一个不带 `--machine` 的 License，
客户端没有任何开关可以关闭绑定校验。

## 兼容说明（2026-07 起）

- 机器码算法从 `MAC+hostname` 换成持久化 `.install_id`。
- 存量已绑定的 License 仍然可用：校验会同时接受 `.install_id`、旧的 `MAC+hostname`、以及仅 MAC 三种指纹。
- `LICENSE_STRICT` 已废弃并被忽略；`docker-compose.yml` 同时固定了 `mac_address` 和 `hostname`。

## 安全要求

- `license_private_key.pem` 只留在卖家本地，绝不能发给客户或放进 Docker 镜像。
- License Key 和客户机器码不要提交 Git 或公开发布。
- 签发记录建议保存：客户、机器码、有效期、套餐、备注。
- 客户迁移服务器时必须重新取机器码并重新签发，不能直接复用严格绑定的旧 License。
