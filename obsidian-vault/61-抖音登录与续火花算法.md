# 抖音登录与续火花算法

> [!info] 上下文 [[60-抖音协议与签名]]

## 1. 扫码登录流程（Playwright）

### 1.1 整体时序

```
浏览器                 Playwright/Chromium          抖音服务器            用户手机
                              │                         │                   │
页面请求二维码 ───────────────▶│                         │                   │
                              │── GET /get_qrcode ────▶│                    │
                              │◀── {qr_b64, qr_url} ───│                    │
           ◀────────── 显示二维码给前端                  │                   │
                                                        │                    │
                      （每秒轮询 cookies.sessionid）      │                    │
                              │                         │◀── 用户扫 QR ─────┤
                              │                         │── 用户点击确认 ───▶│
                              │     （sessionid 下发到 cookies）             │
                              │                         │                    │
                    检测到 sessionid                    │                    │
                              │                                              │
         立即触发 on_logged_in (1 秒内前端跳转)                              │
                              │                                              │
                    （后台继续抓取 init_req）                                 │
                              │── POST /get_message_by_init ─▶               │
                              │◀── init_req.bin binary ──────                │
                              │                                              │
                    抓取完成，写文件                                          │
```

### 1.2 代码关键点（`douyin_im.py:921 qr_login`）

```python
def qr_login(headless=True, qr_sink=None, on_logged_in=None):
    with sync_playwright() as p:
        browser = p.chromium.launch(headless=headless)
        context = browser.new_context(user_agent=UA, viewport={...})
        page = context.new_page()

        # 1) 进登录页，等 get_qrcode 响应
        with page.expect_response(
            lambda r: "get_qrcode" in r.url and r.status == 200,
            timeout=45000,
        ) as qr_info:
            page.goto("https://www.douyin.com/login_page?service=...")
        qr_data = qr_info.value.json().get("data", {})
        qr_b64 = qr_data["qrcode"]          # base64 PNG
        qr_url = qr_data["qrcode_index_url"] # 深链

        qr_sink(qr_b64, qr_url)   # 通知前端显示

        # 2) 轮询 cookies 里的 sessionid
        deadline = time.time() + 120
        while time.time() < deadline:
            cookies = context.cookies()
            dy_cookies = {c["name"]: c["value"] for c in cookies
                          if "douyin" in c.get("domain", "")}
            if dy_cookies.get("sessionid"):
                cookies = {c["name"]: c["value"] for c in cookies}
                break
            time.sleep(1)

        if not cookies.get("sessionid"):
            raise RuntimeError("登录超时，未检测到 sessionid")

        # 3) 立即写 cookies + 触发回调（前端已可跳转）
        _secure_write(COOKIE_FILE, cookies)
        on_logged_in(cookies)

        # 4) 后台继续抓取 init_req（耗时 20-40s）
        page.goto("https://www.douyin.com/")
        with page.expect_request(
            lambda r: "get_message_by_init" in r.url,
            timeout=30000,
        ) as init_info:
            pass
        open(INIT_REQ_BIN, "wb").write(init_info.value.post_data_buffer)

        # 5) 抽 localStorage 私钥（最重要！发消息必备）
        crypt = page.evaluate('localStorage["security-sdk/s_sdk_crypt_sdk"]')
        private_key = json.loads(crypt)["data"]["ec_privateKey"]
        _save_security({"private_key": private_key, ...})
```

### 1.3 常见失败原因

| 场景 | 原因 | 解决 |
|---|---|---|
| `登录超时，未检测到 sessionid` | 云服务器 IP 段被风控 | 改 Windows/家庭宽带 部署（[[21-Windows部署]]） |
| `get_qrcode 响应异常` | UA 或 cookie 初始状态异常 | 重启容器清 Playwright 缓存 |
| 二维码状态错误 | 超过 2 分钟 / 已被扫过 | 重新点【开始扫码】 |
| init_req 抓不到 | 扫码成功但 30s 内抖音没推送 IM 连接 | 页面跳回登录状态，账号被临时限制 |

## 2. 短信登录流程

### 2.1 mix_mode 编码

抖音 SMS 接口要求手机号/验证码经 `mix_mode=1` 编码（`douyin_im.py:534`）：

```python
def _encrypt_mix_mode(s: str) -> str:
    """每字节 XOR 0x05 后 hex 编码"""
    return "".join(f"{b ^ 0x05:02x}" for b in s.encode())
```

示例：
- 明文 `"+86 13800138000"` → bytes → XOR 0x05 → hex → `2b2b2b2b...` 的乱码字符串

### 2.2 发送验证码

```python
POST /passport/web/send_code/
Headers: UA (签名依赖)
Query: aid=6383 & device_platform=web_app & a_bogus=xxx
Body:
  is6Digits=1
  mix_mode=1
  mobile=<mix_mode(mobile)>
  type=<mix_mode("24")>   # 24=登录
  fixed_mix_mode=1
  verify_ticket=<可选>     # 滑块验证通过后的 ticket
```

### 2.3 滑块验证（DDDocr）

如果返回 `error_code in (1104, 2046, 8)` 或含 "captcha"，走滑块流程（`douyin_im.py:492 _handle_douyin_captcha`）：

1. **拿挑战** `GET verify.snssdk.com/captcha/get`
   - 返回：`id` + `url1`（背景图）+ `url2`（滑块图）
2. **DDDocr 识别** `POST http://ocr.example.com/slide_match`
   - 传 background base64 + slider base64
   - 返回：滑块目标 X 坐标
3. **构造轨迹**（`_fake_trajectory`）：生成从 0 到 target_x 的鼠标移动点
4. **提交验证** `POST verify.snssdk.com/captcha/verify`
   - Body: `{id, modified_img_width: 552, reply: 轨迹点, mode: "slide"}`
   - 成功返回 `verify_ticket`
5. **重试发短信**：把 ticket 塞进 send_code 的 body

### 2.4 提交验证码登录

```python
POST /passport/web/sms_login/
Body:
  mix_mode=1
  mobile=<mix_mode(mobile)>
  code=<mix_mode(6位验证码)>
  fixed_mix_mode=1
```

成功后 cookie 里有 sessionid，但 **init_req 和私钥需要再开一次 headless QR 补齐**（因为短信接口不返回这些）。

## 3. 联系人（火花）解析

### 3.1 parse_fire_streaks（字节正则）

**输入**：`get_message_by_init` 的响应 bytes（protobuf）
**输出**：list of `{uid, conv_id, days}`

**实现思路**（`douyin_im.py:1268`）：
- 直接正则匹配字节模式，不反序列化 protobuf（性能最优）
- 找所有 `0:1:<uid>:<uid>` 或 `0:2:<group_id>` 格式的 conv_id
- 在 conv_id 附近找 varint 编码的 `days`（field 3）

```python
CONV_RE = re.compile(rb"0:[12]:[0-9_]+:?[0-9_]*")
def parse_fire_streaks(resp_bytes):
    contacts = []
    for m in CONV_RE.finditer(resp_bytes):
        conv_id = m.group(0).decode()
        # 跳过 conv_id 后找 days varint
        days = _read_vi(resp_bytes, m.end() + 某偏移)[0]
        uid = conv_id.split(":")[2]
        contacts.append({"uid": uid, "conv_id": conv_id, "days": days})
    return contacts
```

为啥用字节正则不用 protobuf：
- 抖音 IM protobuf schema 复杂，字段编号不稳定
- 火花数据嵌套很深
- 字节正则 10ms 内处理几千联系人

### 3.2 fetch_nicknames（昵称兜底）

`parse_fire_streaks` 只出 uid，不带昵称。昵称从 3 个源合并：

1. **Playwright 抓登录时的 `/user/info` / `/relation/follow` 响应**（`_extract_contacts` 拦截）
2. **spotlight/relation signed 接口**
3. **`profile/other` 逐个查**（最可靠，但 N 次请求有风控风险）

```python
def fetch_nicknames(session, contacts):
    captured = {}
    # 已缓存的跳过
    for c in contacts:
        uid = c["uid"]
        if uid in cached_nicks:
            continue
        # 按 user_id 查 profile/other
        qs = _sign_params({"aid": "6383", "user_id": uid, ...})
        r = session.get(f"https://www.douyin.com/aweme/v1/web/user/profile/other/?{qs}")
        data = r.json().get("user", {})
        captured[uid] = {"nick": data.get("nickname", ""),
                         "remark": data.get("remark_name", "")}
        time.sleep(random.uniform(0.3, 0.8))   # 避免风控
    return captured
```

## 4. 发消息算法

### 4.1 proto 构造（`_build_body`）

```python
def _build_body(conv_id, text, contact, c, security):
    # 拆 conv_id: "0:1:<my_uid>:<peer_uid>"
    parts = conv_id.split(":")
    my_uid, peer_uid = parts[2], parts[3]

    # 内嵌 body (cmd=100 SendMessageBody)
    sub_body = (
        _pb_b(1, conv_id)               # conversation_id
        + _pb_v(2, 1)                   # conversation_type = 1 (单聊)
        + _pb_v(3, short_id)            # conversation_short_id
        + _pb_b(4, json.dumps({"text": text}, ensure_ascii=False))   # content
        + _pb_v(6, 7)                   # message_type = 7 (text)
        + _pb_b(7, ticket)              # ticket (来自 init_req)
        + _pb_b(8, client_msg_id)       # client_message_id (唯一)
    )

    # 顶层 Request
    ts_sign = c["ts_sign"]
    sdk_cert = c["sdk_cert"]

    # 签名数据 = conv_id + client_msg_id + ticket + text
    sign_data = conv_id + client_msg_id + ticket + text
    reuqest_sign = _im_req_sign(sign_data, security["private_key"])

    body = (
        _pb_v(1, 100)                   # cmd = 100
        + _pb_v(2, seq_id)              # sequence_id
        + _pb_b(3, "web-5.0.0")         # sdk_version
        + _pb_b(4, token)               # token
        + _pb_b(8, sub_body)            # RequestBody
        + _pb_b(9, device_id)           # device_id
        + _pb_b(11, "web")              # device_platform
        + _pb_b(23, ts_sign)            # ts_sign   ← 见下方 ⚠️
        + _pb_b(24, sdk_cert)           # sdk_cert  ← 见下方 ⚠️
        + _pb_b(25, reuqest_sign)       # request_sign ⭐
    )
    return body
```

> [!danger] ⚠️ ts_sign / sdk_cert 的取值
> **2026-04 起抖音协议升级**：这两字段不再在 `init_req.bin` proto field 23/24，改从浏览器 `localStorage["security-sdk/s_sdk_sign_data_key/web_protect"]` 抽取。
>
> 代码实际取值：
> ```python
> ts_sign  = security.get("ts_sign")     or c.get("ts_sign",  "")
> sdk_cert = security.get("client_cert") or c.get("sdk_cert", "")
> ```
>
> 为空时抖音会**软接受**（API 返 OK 但不投递给对方） → 幽灵发送。
> 详细故障现象和排查见 [[50-故障排查#⭐ 发送"成功"但对方没收到（幽灵发送）]]。

### 4.2 发送（`send_text`）

```python
url = f"https://imapi.douyin.com/v1/message/send?a_bogus={sig}&verifyFp={fp}&..."
r = session.post(url, data=body, headers={"Content-Type": "application/x-protobuf"})
```

**成功判断**：
```python
fields = _pb_flat(r.content)
msg = fields.get(4, b"").decode()    # field 4 = message
edesc = fields.get(3, b"").decode()  # field 3 = error_desc
if msg == "OK" and edesc in ("", "0"):

```

### 4.3 常见错误码

| msg / edesc | 含义 |
|---|---|
| `"OK"` / `"0"` | 成功 |
| `"error_code": 1204` | 非好友/单向好友（不能发消息） |
| `"error_code": 1102` | 账号风控 |
| `"session expired"` | cookie 失效 |
| `"sign verify failed"` | 签名错（多半私钥或 ts_sign 过期） |

## 5. 续火花调度算法

### 5.1 核心循环（`trigger.py:auto_run`）

```python
def auto_run(user_id, account_id, triggered_by="scheduler"):
    lock = _get_account_lock(account_id)
    if not lock.acquire(blocking=False):
        raise AlreadyRunning   # 同账号互斥

    try:
        session, constants, contacts = _ensure_active(ctx)
        templates = load_templates(account_id)

        # 基于历史失败率动态调整间隔
        interval, risk = _adaptive_interval(account_id, base=5.0)
        # 正常: 5s
        # 20-50% 失败: 15s
        # >=50% 失败: 60s

        consecutive_fail = 0
        for i, c in enumerate(contacts):
            msg = _pick_message(c["uid"], c["nickname"], templates)
            if not msg: continue
            if i > 0: time.sleep(interval + random.uniform(-0.5, 0.5))

            ok = send_text(session, c["conv_id"], msg, c, constants)
            if ok:
                consecutive_fail = 0
            else:
                consecutive_fail += 1

            # 连续 5 次失败 → 熔断
            if consecutive_fail >= 5:
                break
    finally:
        lock.release()
```

### 5.2 防风控策略

| 策略 | 实现 |
|---|---|
| **账户互斥** | `_get_account_lock(account_id)` 进程内 lock，防 scheduler + 手动并发 |
| **调度原子 claim** | `UPDATE schedules SET last_ran_date=today WHERE last_ran_date<>today` rowcount==1 才启动，防多进程重复 |
| **自适应限速** | 近 3 次任务失败率 → 调整发送间隔 |
| **连续失败熔断** | 连续 5 个失败立刻停止 |
| **随机抖动** | 每次间隔 ± 0.5s 避免完全匀速 |
| **每日体检** | Scheduler 03:00 跑 cookies 健康检查（指数退避 3 次） |

### 5.3 消息选择（`_pick_message`）

优先级：
1. 联系人独立 `messages` 列表随机一条
2. 没配 → 全局 `default` 模板
3. 都没配 → 跳过不发

```python
def _pick_message(uid, name, templates):
    entry = templates.get(uid) or templates.get(name)
    if entry:
        if not entry.get("enabled", True): return None
        msgs = entry.get("messages", [])
        if msgs: return random.choice(msgs)
    # 回退 default
    fallback = templates.get("default")
    if fallback and fallback.get("enabled", True):
        msgs = fallback.get("messages", [])
        if msgs: return random.choice(msgs)
    return None
```

## 6. 调度器（`scheduler.py`）

### 6.1 扫表循环（30s）

```python
while not STOP:
    hhmm = now.strftime("%H:%M")
    today = now.strftime("%Y-%m-%d")

    rows = db.query(Schedule).filter(
        Schedule.enabled == True,
        Schedule.time_hhmm == hhmm,
        # 原子 claim：只有 last_ran_date 仍不是 today 才更新成功
    )
    for sch, acc, user in rows:
        updated = db.query(Schedule).filter(
            Schedule.id == sch.id,
            or_(Schedule.last_ran_date.is_(None),
                Schedule.last_ran_date != today)
        ).update({"last_ran_date": today})
        db.commit()

        if updated == 1:   # 抢到了
            Thread(target=auto_run, args=(...)).start()

    STOP.wait(30)
```

关键：**原子 UPDATE WHERE + rowcount==1** 保证多进程部署下同一账户只触发一次。

### 6.2 cookies 健康检查（每天 03:00）

```python
def _health_loop():
    while not STOP:
        if now.hour == 3 and today != last_ran:
            for acc in active_accounts:
                _cookies_health_check(acc.id, max_retries=3)
                # 指数退避 2s → 4s → 8s，连续 3 次 NotReady 才标失效

```

避免网络抖动误判 cookies 失效。

## 7. 优化历程

本项目在迭代中解决的关键问题：

- ⭐ 扫码加速：从 40s 跳转降到 1-2s（[[20-部署流程]] 签发 → [[40-开发流程]]）
