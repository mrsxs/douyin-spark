# 架构与技术栈

> [!info] 上下文 [[00-总览]] · 详细部署 [[20-部署流程]]

## 技术栈

### 后端
- Python 3.13
- FastAPI（路由 + ASGI）
- SQLAlchemy 2.0（ORM）
- SQLite（WAL 模式）
- bcrypt（密码哈希）
- itsdangerous（CSRF 签名）
- cryptography（Fernet 加密：cookies / SMTP 密码 / LLM key）
- Playwright（抖音扫码登录的 headless Chromium）

### 前端
- Jinja2（服务端模板）
- Alpine.js 3（响应式交互，无构建）
- Tailwind CSS CDN（样式）
- 原生 `<dialog>` 元素（modal，自带焦点陷阱）

### 部署
- Docker（两阶段：Playwright 浏览器层 + 运行时层，无编译/混淆步骤）
- Docker Compose v2
- GitHub Actions（ruff + pytest 通过后构建镜像推 GHCR，并做镜像内自检）

## 数据持久化

compose 用 bind mount 把宿主机的 `data/` 挂到容器 `/data`（默认在 compose 文件旁边，
`DATA_VOLUME_PATH` 可改成绝对路径）。内容：

```
/data/
├── app.db                       SQLite 主库
├── .secret_key                  自动生成的 SECRET_KEY（持久化）
├── .admin_initialized           首次创建 admin 标记
└── users/
    └── <user_id>/
        └── accounts/
            └── <account_id>/
                ├── cookies.json          🔐 Fernet 加密
                ├── security.json         🔐 Fernet 加密（私钥/签名密钥）
                ├── init_req.bin          IM 会话初始化数据
                ├── contacts.json         联系人昵称缓存
                ├── templates.json        模板备份（DB 是真理之源）
                └── logs/
                    └── YYYY-MM-DD.log
```

> [!warning] 备份必备
> 备份 `data/` = 备份所有 cookies / 私钥 / DB / 模板。一旦丢失，所有抖音账号都要重新扫码登录；
> `.secret_key` 丢了则所有 Fernet 加密字段（cookies、SMTP 密码、LLM key）全部解不开。

## 核心安全机制

| 层 | 机制 |
|---|---|
| **认证** | bcrypt 密码 + 签名 cookie session |
| **CSRF** | 自研 ASGI middleware（body 透传） + double-submit cookie + Referer 净化 |
| **授权** | 无。开源自部署，任何人注册即可用；管理员可停用账号 + 调整配额 |
| **敏感数据** | cookies / 私钥 / SMTP 密码 / LLM key 走 Fernet 加密（密钥派生自 SECRET_KEY） |
| **请求** | CSRF middleware 限制 body 2 MiB（防 DoS） |
| **DB** | SQLite WAL + busy_timeout=5000 + foreign_keys=ON |
| **并发** | account_id 进程内互斥 + scheduler 原子 claim（防重复触发） |
