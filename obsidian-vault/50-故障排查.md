# 故障排查

> [!info] 上下文 [[00-总览]] · 运维 [[30-运维操作]]

按症状分类，先看症状再到对应章节。

## 部署阶段

### 容器启动后立刻退出

```bash
docker compose logs --tail 50
```

常见原因：
- **❌ 许可验证失败 / LICENSE_KEY 未设置** → 检查 `.env` 是否存在且有 `LICENSE_KEY=`
- **❌ License 已过期** → 走 [[30-运维操作#License 续期]]
- **❌ License 签名无效** → 复制时是否漏了字符？需要含 `.` 分隔的两段 base64
- **数据库锁定** → 先停所有相关容器再启 `docker compose down && docker compose up -d`

### `docker compose pull` 报 LICENSE_KEY missing

错误：
```
error while interpolating services.app.environment.LICENSE_KEY: required variable LICENSE_KEY is missing a value
```

原因：当前目录没有 `.env`，或 `.env` 里没有 `LICENSE_KEY=` 这行。

解决：进入 `/opt/douyin-spark`（或 `~/douyin-spark`），确认 `.env` 存在并包含 `LICENSE_KEY=...`：
```bash
cat .env | head -5
```

### `docker-compose.yml` 报 `non-string key at top level: 404`

原因：从私有 GitHub repo 用 `curl raw.githubusercontent.com` 下载时返回了 404 HTML 而不是 yml 文件。

解决：用 Gist 公开 URL（详见 [[20-部署流程]]）：
```bash
curl -sL "https://gist.githubusercontent.com/mrsxs/eb80f17ecee1944c83deb5e0c33d2d78/raw/docker-compose.yml" -o docker-compose.yml
```

## 登录阶段

### 用户名或密码错误

按概率排序排查：

1. **首次启动还没看到密码** → `docker compose logs | grep -A 8 "管理员账户"`
2. **密码 hash 损坏**（shell quoting 问题） → 重置密码，详见 [[30-运维操作#重置管理员密码]]
3. **admin 用户根本不存在** → 用方法 3 inline python 检查 + 创建
4. **找不到 app 模块**（`No module named 'app'`） → 用 `--workdir /app` + cp 到 `/app/` 跑

```bash
# 检查当前 admin 状态
docker exec douyin-spark python -c "
from app.db import SessionLocal
from app.models import User
with SessionLocal() as db:
    for u in db.query(User).all():
        print(f'id={u.id} user={u.username} active={u.is_active} admin={u.is_admin} hash={u.password_hash[:20]}...')
"
```

### License 验证失败

#### 当前机器码不匹配
说明 license 是绑机器签的（严格模式），但当前机器换了：
```bash
# 服务器查机器码
docker exec douyin-spark python -c "from app.license import _machine_id; print(_machine_id())"
# 拿这个码去本地重新签 license
python3 tools/issue_license.py --days 365 --machine 当前机器码
```

#### License 已过期
详见 [[30-运维操作#License 续期]]

#### 签名无效
- 重新复制 license string 确保完整（含两段，中间一个 `.`）
- 检查 `.env` 编辑时是否有不可见字符或换行
- 极端情况：是否动了 `app/license.py` 公钥？

## 抖音相关

### 扫码后不跳转

按设计扫码成功后会立即跳，但 init_req/私钥后台抓取可能 30s。如果跳转后看到 `init_req.bin 不存在`，等几秒刷新即可（前端自动 5s reload）。

### 联系人显示 uid 不显示昵称

抖音 API 有时不返回昵称，需要触发 `fetch_nicknames`：账户详情页点【刷新联系人】按钮。

### 「测试发送」点了没反应

可能是浏览器装了 `disable_dialogs` 类脚本拦截了 `confirm()` / `prompt()`。本项目 modal 已全部改成原生 `<dialog>` 不会被拦。如果仍有问题：硬刷浏览器 `Cmd+Shift+R`。

### 自动续火花全部失败

主要原因：
1. cookies 失效 → 账户详情页【🩺 体检登录态】，失效会引导重登
2. 抖音风控 → 看 [[30-运维操作#查看日志]] 找 `error_desc`，必要时账号暂停几小时
3. 模板没启用 → 联系人列表里是否所有 toggle 都是关的？

## CI / 镜像

### Actions 构建失败

```bash
gh run view <run-id> --log-failed | tail -50
```

常见原因：
- Dockerfile 引用了被 .dockerignore 排除的文件
- 依赖装不上（PyPI 临时挂了，重跑就行）
- Cython 编译某个文件失败 → 那个文件加到 `setup_ext.py` 的 KEEP 列表

### Docker Hub pull 不到镜像

```bash
docker pull mrsxs/douyin-spark:latest
```

公开镜像免登录。如果 503/timeout：
- 检查网络
- 国内服务器配 Docker Hub 镜像加速器

### Gist 拿到的脚本是旧版

GitHub CDN 缓存约 5 分钟。强制最新：用带 commit hash 的 URL：
```bash
HASH=$(curl -sL "https://api.github.com/gists/eb80f17ecee1944c83deb5e0c33d2d78" | grep -o '"version":"[a-f0-9]*"' | head -1 | cut -d'"' -f4)
curl -sL "https://gist.githubusercontent.com/mrsxs/eb80f17ecee1944c83deb5e0c33d2d78/raw/$HASH/manage.sh" -o manage.sh
```

## 容器内调试

### 进容器 shell

```bash
docker exec -it douyin-spark bash
# 容器内：
cd /app
ls
python -c "from app.config import settings; print(settings.dict())"
```

### 看 SQLite 数据

```bash
docker exec douyin-spark sh -c "sqlite3 /data/app.db '.tables'"
docker exec douyin-spark sh -c "sqlite3 /data/app.db 'SELECT * FROM users;'"
```

### 检查 cookies 是否加密

```bash
docker exec douyin-spark sh -c "head -c 8 /data/users/1/accounts/2/cookies.json"
# 输出 ENCv1: 表示已加密
# 输出 { 表示明文（可能是迁移前的旧账户）
```
