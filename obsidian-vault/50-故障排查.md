# 故障排查

> [!info] 上下文 [[00-总览]] · 运维 [[30-运维操作]]

按症状分类，先看症状再到对应章节。

## 部署阶段

### 容器启动后立刻退出

```bash
docker compose logs --tail 50
```

常见原因：
- **数据库锁定** → 先停所有相关容器再启 `docker compose down && docker compose up -d`
- **`DATA_VOLUME_PATH` 指向的目录没权限** → `ls -ld` 看一眼，容器里是 root 写
- **迁移报错** → `docker compose logs | grep init_db`，看是哪一条 DDL 挂了

> [!note] 旧版本的 LICENSE_KEY 相关启动失败已经不存在
> 授权码体系（`LICENSE_KEY` 启动闸门 + 用户授权码）已整体移除。
> `.env` 里残留的 `LICENSE_KEY=` 会被直接忽略，可以删掉。
> 从旧版升级见 [DEPLOY.md 第 7 节](../DEPLOY.md#7-从旧的授权码版本迁移)。

### `docker-compose.yml` 报 `non-string key at top level: 404`

原因：`curl` 下载时拿到的是 404 HTML 而不是 yml 文件（URL 写错，或仓库/分支名不对）。

解决：确认 URL 和下载结果：
```bash
curl -fsSL https://raw.githubusercontent.com/mrsxs/douyin-spark/main/docker-compose.yml -o docker-compose.yml
head -3 docker-compose.yml     # 应该看到 services:
```

`-f` 会让 curl 在 HTTP 错误时直接失败，而不是把错误页写进文件。

## 登录阶段

### 用户名或密码错误

按概率排序排查：

1. **首次启动还没看到密码** → `docker compose logs | grep -A 8 "管理员账户"`
2. ⭐ **bcrypt hash 在 .env 被 docker compose 截断**（详见下方 [[#部署时设密码登录失败]]）
3. **密码 hash 损坏**（shell quoting 问题） → 重置密码，详见 [[30-运维操作#重置用户密码]]
4. **admin 用户根本不存在** → 用方法 3 inline python 检查 + 创建
5. **找不到 app 模块**（`No module named 'app'`） → 用 `--workdir /app` + cp 到 `/app/` 跑

```bash
# 检查当前 admin 状态
docker exec douyin-spark python -c "
from app.db import SessionLocal
from app.models import User
with SessionLocal() as db:
    for u in db.query(User).all():
        print(f'id={u.id} user={u.username} active={u.is_active} admin={u.is_admin} hash={u.password_hash[:20]}...')
"

# 验证 hash 和密码是否对得上
docker exec -e P='你输入的密码' douyin-spark python -c "
import os, bcrypt
from app.config import settings
print('match:', bcrypt.checkpw(os.environ['P'].encode(), settings.admin_password_hash.encode()))
print('hash 长度:', len(settings.admin_password_hash))   # 应是 60
"
```

### 部署时设密码登录失败 ⭐ 经典坑

> [!danger] 症状
> 用 manage.sh / manage.ps1 [1] 安装时设的自定义密码 → 登录失败
> 但用 [2] 重置密码 → 立刻能登
>
> Root cause：bcrypt hash 含 `$` 被 docker compose 当变量引用截断

**详细原理**：

bcrypt hash 格式 `$2b$12$g67UUAsETEYA9v.0V3J3j.JxCkRiKCe...`

写到 `.env`：
```ini
ADMIN_PASSWORD_HASH=$2b$12$g67UUAsETEYA9v.0V3J3j.JxCkRiKCe...
```

docker compose 解析 .env 时把：
- `$2b` 当变量 `2b` 引用 → 不存在 → 空字符串
- `$12` 当变量 `12` 引用 → 空
- `$g67U...` 当变量引用 → 空

最终容器拿到的 ADMIN_PASSWORD_HASH 变成 `bg67UUAsETEYA9v.0V3J3j.JxCkRiKCe...`（缺了 `$2$12$`，前缀错了，bcrypt verify 全失败）。

**修复（已在新版 manage.sh / manage.ps1 中）**：写 `.env` 前转义 `$` → `$$`

```bash
# Bash
ESCAPED=$(printf '%s' "$ADMIN_HASH" | sed 's/\$/$$/g')
echo "ADMIN_PASSWORD_HASH=$ESCAPED" >> .env
```

```powershell
# PowerShell
$escaped = $ADMIN_HASH -replace '\$', '$$'
"ADMIN_PASSWORD_HASH=$escaped" | Add-Content .env
```

docker compose 读 `$$` 自动还原成 `$`，容器拿到完整 hash。

**自检命令**：

```bash
# 看实际写入 .env 的内容（应该是双 $$）
grep ADMIN_PASSWORD_HASH /opt/douyin-spark/.env
# 正确：ADMIN_PASSWORD_HASH=$$2b$$12$$g67U...
# 错误：ADMIN_PASSWORD_HASH=$2b$12$g67U...

# 看容器最终拿到的（应该是单 $）
docker exec douyin-spark printenv ADMIN_PASSWORD_HASH
# 正确：$2b$12$g67U...（长度 60）
# 错误：bg67U...（长度 < 60，前缀不对）
```

**如何修旧的部署**：

不用动 .env，直接用 [2] 重置密码（[[30-运维操作#重置用户密码]]），inline python 直接改 DB 跳过 .env。或者重新走 [1]（用新版 manage.sh / manage.ps1）。

## 抖音相关

### 扫码后不跳转

按设计扫码成功后会立即跳，但 init_req/私钥后台抓取可能 30s。如果跳转后看到 `init_req.bin 不存在`，等几秒刷新即可（前端自动 5s reload）。

### 联系人显示 uid 不显示昵称

抖音 API 有时不返回昵称，需要触发 `fetch_nicknames`：账户详情页点【刷新联系人】按钮。

### 「测试发送」点了没反应

可能是浏览器装了 `disable_dialogs` 类脚本拦截了 `confirm()` / `prompt()`。本项目 modal 已全部改成原生 `<dialog>` 不会被拦。如果仍有问题：硬刷浏览器 `Cmd+Shift+R`。

### 自动续火花全部失败

主要原因：
1. cookies 失效 → 账户详情页【🩺 体检登录态】，失效会引导重登
2. 抖音风控 → 看 [[30-运维操作#查看日志]] 找 `error_desc`，必要时账号暂停几小时
3. 模板没启用 → 联系人列表里是否所有 toggle 都是关的？

### ⭐ 发送"成功"但对方没收到（幽灵发送）

> [!danger] 最隐蔽的坑 · 2026-04 真实踩过
> 日志显示 `✓ 发送成功 (server: OK)` + `f5: 0` + 服务端生成消息 ID，但**对方抖音 App 里什么都没收到**。

#### 根本原因

**抖音协议升级**：`ts_sign` / `sdk_cert` 不再放在 `init_req.bin` 的 field 23/24，改为放在浏览器 `localStorage["security-sdk/s_sdk_sign_data_key/web_protect"]` 里。

Playwright 扫码时已经把这俩字段抽到 `security.json`，但**旧版 `_build_body` 只从 `init_req.bin` 取** → 取到空字符串 → 抖音**软接受**（返回 `OK`、记录消息 ID、给 f5=0）**但不投递到对方客户端**。

#### 修复（已合并到 main）

`douyin_im.py:1540-1541` 优先从 `security.json` 取：

```python
ts_sign    = security.get("ts_sign") or c.get("ts_sign", "")
sdk_cert   = security.get("client_cert") or c.get("sdk_cert", "")
```

#### 自检：已安装的服务器是否受影响

```bash
docker exec --workdir /app douyin-spark python -c "
from app.storage import set_account_ctx, AccountCtx
set_account_ctx(AccountCtx(1, 1))
import douyin_im as dy
sec = dy._load_security()
print('ts_sign 长度:', len(sec.get('ts_sign', '')))
print('client_cert 长度:', len(sec.get('client_cert', '')))
"
```

- 都 > 0 → 扫码时抓到了，升级镜像就修好（`docker compose pull && up -d`）
- 都 0 → Playwright 抓 localStorage 失败了，需要**重新扫码登录**

#### 判断流程

```
发送失败对方没收到
  │
  ├─→ 先在手机抖音 App 里看"对方"聊天历史
  │     │
  │     ├─ 有你发的消息 → 对方没看 / 屏蔽通知（不是程序问题）
  │     ├─ 没有任何消息 → 继续排查
  │     └─ 对方列表消失 → 对方删了你（API 再 OK 也到不了）
  │
  ├─→ 查 security.json（见上自检命令）
  │     │
  │     ├─ ts_sign 空 → 重新扫码，让 Playwright 抓 localStorage
  │     └─ ts_sign 有 → 升级镜像（用新版 _build_body）
  │
  └─→ 升级镜像后再测
        │
        └─ 对方 App 看到 → 修复成功 ✓
```

### 🔴 容器重建后数据"不见了"（named volume 遗留）

**症状**：
- 原来能登录 / 有抖音账号
- 某次 `docker compose up -d` 重建容器后 admin 密码不管用、抖音账号状态变成"待登录"
- `ls .\data\` 里的 `app.db` 只 4KB（空壳）

**原因**：
早期 `docker-compose.yml` 用 named volume `spark-data`，后来改为 bind mount `./data`。改完后**老数据还在 named volume**，容器启动却读新的空 `./data`。

**检查**：
```powershell
docker volume ls | Select-String spark
# 若看到 douyin-spark_spark-data（老的 named volume） → 数据在里面
```

**迁移**：
```powershell
# 1. 停容器
docker compose stop

# 2. 清空新的空壳 data
Remove-Item -Recurse -Force .\data\*

# 3. 老 volume → 新 bind mount 整拷
docker run --rm `
  -v douyin-spark_spark-data:/src `
  -v "${PWD}\data:/dst" `
  alpine sh -c "cp -rp /src/. /dst/"

# 4. 启动
docker compose up -d

# 5. 验证
docker exec --workdir /app douyin-spark python -c "
from app.db import SessionLocal; from app.models import User, DouyinAccount
with SessionLocal() as db:
    for u in db.query(User).all(): print(f'user: {u.username}')
    for a in db.query(DouyinAccount).all(): print(f'acc: {a.label} {a.status}')
"
```

Linux 同理，替换 PowerShell 语法为 bash：
```bash
rm -rf ./data/*
docker run --rm -v douyin-spark_spark-data:/src -v "$(pwd)/data:/dst" \
  alpine sh -c "cp -rp /src/. /dst/"
docker compose up -d
```

迁移完**老名 volume 可以删**（确认新数据 OK 后）：
```bash
docker volume rm douyin-spark_spark-data
```

### 🔴 定时任务时间差 8 小时（时区 bug）

**症状**：Web 后台设定时 `22:36`，实际不触发 / 到第二天早上 06:36 才触发。

**原因**：容器默认 UTC 时区，scheduler `datetime.now()` 拿 UTC，但你想要北京时间。

**验证**：
```powershell
docker exec douyin-spark date
# 输出 UTC xx:xx:xx → 是问题
# 输出 CST xx:xx:xx → OK
```

**修复**：`docker-compose.yml` 的 `environment:` 段加一行：
```yaml
TZ: "Asia/Shanghai"
```

`docker compose up -d` 重建容器生效。仓库里的 compose 已默认带 TZ。

### jsrsasign 模块缺失（签名失败）

**症状**：日志有 `⚠ reuqest_sign 生成失败: Cannot find module 'jsrsasign'`，但 HTTP 200 OK。

原因：Dockerfile 没装 npm 依赖。已在 2026-04 修复，Dockerfile runtime 阶段加：

```dockerfile
RUN apt-get install -y nodejs npm
COPY package.json /app/package.json
RUN npm install --omit=dev
```

验证：
```bash
docker exec douyin-spark node -e "require('jsrsasign'); console.log('ok')"
# 应输出 ok
```

没装的话升级镜像解决。

## CI / 镜像

### Actions 构建失败

```bash
gh run view <run-id> --log-failed | tail -50
```

常见原因：
- Dockerfile 引用了被 .dockerignore 排除的文件
- 依赖装不上（PyPI 临时挂了，重跑就行）
- 镜像自检没过 → 看 `tools/image_selfcheck.py` 报的是哪一步（router import / healthz / 表单登录）

### pull 不到镜像

```bash
docker pull ghcr.io/mrsxs/douyin-spark:latest
```

公开镜像免登录。如果 503/timeout：
- 检查网络
- 国内服务器配镜像加速器（Docker Desktop → Settings → Docker Engine → `registry-mirrors`）

### 拿到的部署脚本是旧版

raw.githubusercontent.com 有 CDN 缓存（约 5 分钟）。急着要最新的就带上 commit sha：

```bash
SHA=$(gh api repos/mrsxs/douyin-spark/commits/main --jq .sha)
curl -fsSL "https://raw.githubusercontent.com/mrsxs/douyin-spark/$SHA/manage.sh" -o manage.sh
```
