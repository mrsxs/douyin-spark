# 部署流程

> [!info] 上下文 [[00-总览]] · 运维 [[30-运维操作]] · 故障 [[50-故障排查]]
>
> 面向使用者的完整版在 [DEPLOY.md](../DEPLOY.md)，这里只记「为什么这么做」和踩过的坑。

## 一键部署（推荐）

```bash
curl -fsSL https://raw.githubusercontent.com/mrsxs/douyin-spark/main/deploy.sh -o deploy.sh
chmod +x deploy.sh && ./deploy.sh
```

向导两步，**都可以回车跳过**：

1. `DOUYIN_CAPTCHA_KEY` + URL —— 自建 ddddocr 滑块服务，只有短信登录用得上
2. `ADMIN_PASSWORD` —— 自定义（隐藏输入 + 二次确认）或回车让容器随机生成

脚本自动：下载 compose → `docker pull` → 用镜像里的 bcrypt 算密码哈希 → 写 `.env`（chmod 600）→ `up -d` → 等健康检查 → 打印访问地址。

> [!note] 为什么在镜像里算 bcrypt
> 宿主机不一定有 Python，更不一定有 `bcrypt`。用刚拉下来的镜像跑一次性容器算，
> 保证哈希用的是和运行时完全一致的 bcrypt 版本和 cost。

## 运维菜单（可选）

`manage.sh` / `manage.ps1` 是交互式菜单版，多包了「改密码」「看状态」「卸载」：

```bash
curl -fsSL https://raw.githubusercontent.com/mrsxs/douyin-spark/main/manage.sh -o manage.sh
chmod +x manage.sh && ./manage.sh
```

```
  [1] 安装 / 启动 / 升级服务
  [2] 重置用户密码      详见 [[30-运维操作#重置用户密码]]
  [3] 查看状态 & 日志
  [0] 退出
```

Windows 用 `manage.ps1`，见 [Windows安装指南](../Windows安装指南.md)。

## 手动部署

```bash
mkdir -p /opt/douyin-spark && cd /opt/douyin-spark
curl -fsSL https://raw.githubusercontent.com/mrsxs/douyin-spark/main/docker-compose.yml -o docker-compose.yml

# .env 可以完全不写 —— 所有配置项都有默认值
docker compose up -d
docker compose logs | grep -A 8 "管理员账户"
```

首启没配 `ADMIN_PASSWORD_HASH` 时，`docker-entrypoint.sh` 生成 20 位随机密码并**只打印这一次**，
同时 touch 一个 `/data/.admin_initialized` 标记防止重启又生成一遍。

## 踩过的坑

> [!danger] `.env` 里的 bcrypt 哈希必须转义 `$`
> docker compose 会把 `.env` 里的 `$2b$12$xxx` 当变量插值，实际注进容器的是被截断的串 ——
> 表现是「密码明明设对了却登不上」。写入时必须 `$` → `$$`。
> `deploy.sh` / `manage.sh` / `manage.ps1` 都做了这个转义。

> [!danger] 容器不设 `TZ` 会走 UTC
> 定时触发时间直接差 8 小时。compose 里已经默认 `Asia/Shanghai`，自己写 compose 的记得加。

> [!warning] 判断「是否已部署过」不能盯单个 env 变量
> 旧版本 `deploy.sh` 用 `grep -q "LICENSE_KEY=.\+" .env` 判断。去掉授权码后 `.env` 里
> 已经没有任何必填项了，这个判据会把已有部署误判成全新安装，**把用户配好的管理员密码覆盖掉**。
> 现在改成判断 `.env` 存在且非空（`[ -s .env ]`）。

## 内网 IP

服务器只有内网 IP（`10.x.x.x` / `172.x`）时，外部访问需要云厂商给的公网 IP，或绑域名 + 反代。

## HTTPS 反代

Caddy 最省事（自动签证书）：

```caddyfile
yourdomain.com {
    reverse_proxy localhost:8765
}
```

上了 HTTPS 之后两件事必须做：

1. `.env` 设 `COOKIE_SECURE=true` 并重启 —— 否则 session cookie 不带 `Secure` 标记
2. 确认反代确实在设 `X-Forwarded-For`

> [!warning] X-Forwarded-For 是双刃剑
> 限流按这个头取客户端 IP（`app/ratelimit.py:_client_key`）。它是客户端可伪造的，
> **只有在可信反代后面才有意义**。如果直接把 8765 暴露到公网，这个分支反而应该关掉，
> 否则攻击者换个 header 就绕过了限流。

Nginx 还要额外加 `proxy_buffering off`，否则 SSE（运行进度、新消息推送）会被缓冲，页面一直转圈。

## 升级

```bash
cd /opt/douyin-spark
docker compose pull && docker compose up -d
```

或再跑一次 `./deploy.sh`（检测到已有 `.env` → 直接走升级分支，不重新问配置）。

DB 迁移在启动时自动跑（`app/db.py:init_db()`，幂等加列 + 补索引），不需要手动执行任何迁移命令。
看有没有跑完：`docker compose logs --tail 50 | grep init_db`

## 镜像

```yaml
image: mrsxs/douyin-spark:latest        # Docker Hub，公开免登录
```

GitHub Actions 在 ruff + pytest 通过后构建并推送，然后做一次**镜像内自检**：起 uvicorn 打 `/healthz`，
再走一遍表单登录路径。详见 [[40-开发流程#自动构建链路]]。

> [!danger] 别随手把 compose 换成 GHCR
> CI 也推 `ghcr.io/mrsxs/douyin-spark`，但 **GitHub container package 默认私有**，
> 匿名 `docker pull` 直接 403 —— 新用户一部署就卡在拉镜像那一步。
> 要用 GHCR 得先去 Package settings 把 visibility 改成 Public，或让部署机
> `docker login ghcr.io`。验证方法：
>
> ```bash
> curl -s "https://ghcr.io/token?scope=repository:mrsxs/douyin-spark:pull&service=ghcr.io"
> # 公开包才会返回 token；私有包这里就拿不到
> ```

想自己构建：把 `image:` 换成 `build: .`，`docker compose up -d --build`。
