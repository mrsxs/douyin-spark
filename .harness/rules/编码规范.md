# 编码规范

> 规则取自本项目已落地的真实写法，新代码照此对齐，别引入第二种风格。

## 命名

- 文件/模块：小写下划线（`templates_service.py`、`login_flow.py`）。
- 类：`PascalCase`（`DouyinAccount`、`AccountCtx`）。
- 函数/变量：`snake_case`。
- 私有 helper：前缀 `_`（`_safe_err`、`_run_one`、`_load_session`）。
- 路由处理函数：`api_<动作>`（`api_refresh`、`api_send`）。
- 常量：全大写（`MAX_DAILY_RETRIES`、`RUNNING_STALE_MINUTES`）。
- 领域术语统一：**火花/续火花**、**账户(account)**=抖音账号、**用户(user)**=SaaS 登录用户。别混用。

## SQLAlchemy 2.0 模型风格

统一用 `Mapped[...]` + `mapped_column(...)`，可空字段写 `Mapped[str | None]`，对齐等号让列定义成块（见 `models.py`）：

```python
class DouyinAccount(Base):
    __tablename__ = "douyin_accounts"
    id:      Mapped[int]        = mapped_column(Integer, primary_key=True)
    user_id: Mapped[int]        = mapped_column(ForeignKey("users.id", ondelete="CASCADE"), index=True)
    status:  Mapped[str]        = mapped_column(String(24), default="pending_login")
```

- 状态用字符串 + 紧邻注释列出取值（`# 'pending_login' | 'active' | 'cookies_expired'`）。
- 时间默认 `default=datetime.utcnow`（注意：传函数本身，不要加括号）。

## 错误处理

- **路由层**：用 `raise HTTPException(状态码, "中文人话")`，例如 `raise HTTPException(400, "缺少 account_id")`、`raise HTTPException(404, "账户不存在")`。
- **业务层异常**：用自定义异常表达可恢复业务态——`trigger.NotReady`（cookies 失效/缺 init_req）、`trigger.AlreadyRunning`（账户互斥锁占用）。它们的 `str()` 就是给用户看的话。
- **返回给前端前必须脱敏**：用 `app/routers/api.py:_safe_err()`。白名单异常（`NotReady`/`AlreadyRunning`/`ValueError`/`KeyError`/`HTTPException`）原文透出（截断 200 字）；其它（DB / 第三方 SDK / 连接错误）一律换成通用文案，**禁止把 SQLAlchemy / traceback / 内部路径泄露给前端**。
- **禁止吞异常**：`except Exception` 后至少 `print("[模块] ... : {e}")` 记录；后台线程（scheduler/notify）可吞但必须打日志，不能静默 `pass`。

## 日志

本项目**不用 logging 模块**，用带方括号模块前缀的 `print`：

```python
print(f"[init_db] 模板迁移完成：{migrated_accounts} 个账户")
print(f"[notify] SMTP 发送失败 host={c.get('host')} port={port}: {e}")
print("[bootstrap] 警告：.env 未配置 ADMIN_USERNAME")
```

- 前缀 = 模块/场景名（`[init_db]` `[notify]` `[config]` `[bootstrap]`）。
- **敏感信息脱敏**：日志里禁止打印 cookies、私钥、SECRET_KEY、SMTP 密码、完整 token。最多打长度或前几位。

## API 响应格式（JSON）

`/api` 下的接口约定：

- 成功：直接返回业务 dict（FastAPI 自动 200 JSON），如 `{"ok": True, "contacts": [...], "filled": 3}`。简单成功用 `{"ok": True}`。
- 失败：`raise HTTPException(状态码, _safe_err(e))`，由全局处理器转 JSON。**不要**手工拼 `JSONResponse({"code": ...})` 制造第三种格式。
- 每个 `/api` 请求带 `account_id`，归属校验交给 `deps`（`require_active` + `get_account_owned`），不要在 handler 里手写归属判断。
- HTML 路由（dashboard/auth）返回 `TemplateResponse` 或 `RedirectResponse`，与 JSON API 分开，互不混用。

## DB 迁移规范（手写，无 Alembic）

迁移全部在 `app/db.py:init_db()`，启动时幂等执行：

- 新表：加进 `models.py`，`Base.metadata.create_all` 自动建。
- 新索引：`create_all` 不会给已存在表补索引 → 在 `init_db` 的 DDL 列表加 `CREATE INDEX IF NOT EXISTS ...`。
- 新列 / 数据迁移：`init_db` 里用 `text(...)` 执行，**必须幂等**（先查后改 / `IF NOT EXISTS`），整段包 `try/except` 并 `print("[init_db] ...")`，失败不可让启动崩溃。
- **只增不改**：向后兼容，不删旧列、不破坏已有数据（用户数据在生产 volume）。

## 文件原子写

写联系人/模板等缓存文件，照 `api.py` 的模式：`tempfile.mkstemp` → 写 → `f.flush()` + `os.fsync()` → `os.replace(tmp, dst)`。禁止直接 `open(path,"w")` 覆盖（会在并发/崩溃时损坏数据）。

## 前端（Jinja2 + Alpine.js + Tailwind CDN，无构建）

- 模板放 `templates/`，按页面分目录；服务端渲染。
- 交互用 **Alpine.js 3**（`x-data`/`x-on`/`x-show`），不引入打包器、不写独立 JS bundle。
- 样式用 **Tailwind CDN** 工具类，不写大段自定义 CSS。
- Modal 用原生 `<dialog>`（自带焦点陷阱），不要自造遮罩。
- 所有改数据的表单/请求必须带 CSRF token（`csrf_mw.py` 校验）。
